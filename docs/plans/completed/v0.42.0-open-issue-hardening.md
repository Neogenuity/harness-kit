# Open-issue hardening and observational eval foundations

Status: completed — shipped in v0.42.0

## Objective

Resolve the validated defects and adoption gaps in GitHub issues #29–#35, and
land the provider-neutral trace, trajectory analysis, and local
observation-to-regression foundation from #36 without weakening the existing
controlled-eval contract.

## Value

The current issue set came from real adopter evidence: OpenCode lacks the
feedback layer, synthetic tests can corrupt operational telemetry, retry and
plan-cycle reports cannot receive the metadata they require, the eval bank is
hard to start, secret-command denials lose their path, and the event log has no
retention stance. Fixing these together closes the loop from live behavior to
trusted regression tasks instead of adding another disconnected feature.

## Scope

1. **OpenCode hook adapter (#29)** — ship and validate a project-local plugin
   that maps OpenCode tool/session hooks onto the portable hook scripts.
   *Acceptance: provider derivation includes OpenCode hook wiring; adapter tests
   prove pre-tool denial, post-edit feedback, session context, and shell session
   attribution.*
2. **Telemetry integrity (#30, #34, #35)** — keep repo-authored guard tests from
   writing operational events, record the matched shell token on secret denials,
   and define/test a bounded retention and audit-window workflow.
   *Acceptance: regression fixtures reproduce the former noise/empty-path cases
   and pass with clean, attributable output; the telemetry standard documents
   what pruning loses and how to do it safely.*
3. **Session and plan attribution (#31, #32)** — use provider-native session
   environment channels rather than shared last-writer state, add explicit plan
   lifecycle metadata, validate it, and reduce completed cycles.
   *Acceptance: Claude, Codex, and OpenCode gate events carry a session id without
   cross-session state; valid completed plan metadata yields deterministic cycle
   rows while legacy plans remain visibly unavailable rather than guessed.*
4. **Eval adoption floor (#33)** — ship two stack-independent seed scenarios and
   a draft-first authoring command that cannot enter the trusted bank before its
   deterministic grader and reference solution are complete.
   *Acceptance: shipped grader-validity checks pass both seeds and skip draft
   scaffolds until explicitly activated.*
5. **Observational eval foundation (#36)** — normalize Claude/Codex transcripts
   into a versioned provider-neutral trace, compute deterministic trajectory
   findings in controlled evals, and add local import, feedback, and draft
   promotion commands.
   *Acceptance: both transcript fixtures normalize to the same schema; at least
   five trajectory metrics are recorded without changing task pass/fail or
   baseline semantics; imported runs stay under `.harness/var/`; promotion
   creates an untrusted draft, never an accepted grader.*
6. **Review and publication** — roll template changes into this repo's installed
   harness, run the complete gate set, obtain adversarial subagent reviews, fix
   actionable findings, and publish one draft PR with issue-by-issue evidence.
   *Acceptance: `bash scripts/harness/verify` passes after review fixes and the
   draft PR links #29–#36 with explicit closed-versus-follow-up status.*

## Out of scope

Automatic hosted transcript collection, OTLP or third-party observability
exports, LLM trajectory judges, and mandatory observational CI gates remain
future #36 phases. This PR provides a local import path and deterministic
foundation only. Cutting/tagging v0.42.0 is separate release work.

## Dependencies

OpenCode's documented project plugin API (`tool.execute.before`,
`tool.execute.after`, `shell.env`, and session-aware system transforms), Claude
Code's documented `CLAUDE_ENV_FILE`, and the existing v0.41.0 eval and telemetry
schemas.

## Verification

Run targeted changed suites during each issue iteration, then
`bash scripts/harness/verify`. Validate new JSON artifacts against their schemas,
exercise the OpenCode adapter with a mocked Node host, prove both seed graders
in the shipped floor, and have independent subagents review correctness,
security/fail-open behavior, compatibility, and test adequacy before the final
full-gate rerun.

## Progress

- 2026-08-12 — Windows proved synchronous timeout was not enough when Bash
  descendants retained stdio. The OpenCode adapter now awaits a bounded child
  runner, drains at most 64 KiB per stream, fails open on stdin/process errors,
  terminates POSIX groups or Windows trees on timeout, and reserves concurrent
  context injection before awaiting. Adversarial regressions pin early-exit
  EPIPE, output floods, real descendant death, taskkill fallback, async
  overrides, and same-session concurrency; both closure audits are clean.
- 2026-08-12 — The Windows floor also exposed an MSYS/native-Node boundary in
  the OpenCode adapter test: `/tmp` is not a valid native Windows file URL.
  The executable harness now converts test paths with `cygpath` before Node's
  `pathToFileURL`, while still exercising the adapter's real Bash child path;
  CI now prints any nonzero suite even when it lacks a standard failure marker.
- 2026-08-12 — The Windows/Git Bash floor confirmed its established NTFS
  limitation: `chmod 600` leaves the reported mode unchanged. Observation
  behavior remains fully asserted there, while the POSIX privacy-mode check is
  skipped only after an independent non-executable-mode capability probe; hosts
  that can record modes still require exact `0700/0600` results.
- 2026-08-11 — GitHub's Ubuntu harness-check exposed a portability defect in
  the observation test's permission assertion: GNU `stat` accepted the BSD
  option shape but returned filesystem metadata. The assertion now validates
  the GNU result before falling back to BSD output, and both installed/template
  copies pass their focused suites.
- 2026-08-11 — Final `bash scripts/harness/verify --jobs 8` passed every full
  quality gate after the adversarial corrections: templates, provider wiring,
  installs/migrations/recovery, checker, evals/graders, runtime fixture, and
  installed harness coherence.
- 2026-08-11 — Semantic, security/fail-open, and measurement adversaries all
  closed their findings after re-auditing the corrected tree. The last closure
  pass added tri-state instruction ordering and nested/type-shape tolerance so
  incomplete provider evidence stays unknown instead of becoming a false
  trajectory claim.
- 2026-08-11 — Corrected the adversarial-review findings: completed Claude
  file operations now require successful tool results; Codex instruction
  discovery reports unavailable instead of false; recovery requires a matching
  command retry; the seed grader rejects suffix attacks; observations stage
  privately and atomically; promotion redacts paths; draft activation runs the
  independent grader-validity suite; OpenCode hooks time out fail-open and its
  executable adapter is integrity-pinned; rotation handles concurrency and
  dead owners silently; unrelated plan frontmatter remains compatible.
- 2026-08-11 — Rolled 62 mechanism files into the installed dogfood harness.
  Focused trace, observation, OpenCode, log, eval, plan, template-sync, and
  checker suites pass after the corrections; the installed harness is coherent.
- 2026-08-11 — Validated all eight open issues against v0.41.0. Reproduced #30
  and #34 locally; confirmed #29 against the current OpenCode plugin API; found
  concurrency-safe provider environment channels for #31; scoped #36 to its
  local deterministic foundation.

## Decisions

- 2026-08-11 — Reject a shared session-id state file because concurrent parent
  and subagent sessions in one worktree can silently misattribute gate events;
  use provider-native environment propagation and explicit provenance instead.
- 2026-08-11 — Keep #36's hosted integrations and semantic judges out of this
  release because they are optional consumers of the normalized trace, not
  prerequisites for proving the local regression loop.
- 2026-08-11 — Promotion creates an underscore-prefixed draft scenario because
  the eval runner and grader-validity floor already exclude underscore-prefixed
  templates; an inferred grader must never become trusted by automation.
- 2026-08-11 — Treat provider evidence coverage as data: Codex exports without
  read events produce nullable instruction-discovery fields, never a synthetic
  negative observation.
- 2026-08-11 — A draft name is not a trust boundary. Marker-bearing drafts are
  unexecutable even after rename, and `eval-author finalize` activates them
  only after placeholder removal and independent reference/grader validation.
